# Borshchuk Education — освітня платформа

Borshchuk Education (раніше StudyFlow) — повнофункціональна система [на сайті](https://studyflow-rozklad.vercel.app) на **React + TypeScript + Vite + Supabase**. У браузері: тижневий та місячний календар, пошук, експорт CSV, внутрішні сповіщення, статистика, профілі, керування групами, журнал аудиту. У базі: реєстрація email/пароль, ролі студент / викладач / адміністратор, RLS, автоматичні записи аудиту.

> **ВАЖЛИВО — НЕ ЗАВАНТАЖУЙ ЦЮ ВЕРСІЮ В `main` ПОКИ НЕ ВИКОНАЄШ SQL-МІГРАЦІЮ!** Старий сайт працює без входу. Новий потребує нові таблиці та RLS. При виконанні SQL стара версія тимчасово втратить доступ до розкладу. Обирай момент, коли користувачі не редагують дані.

## Реалізовані функції

- Реєстрація та вхід за email і паролем через Supabase Auth, вихід, форма запиту відновлення пароля.
- Профіль зі справжньою роллю з БД; реєстрація завжди створює `student`, роль неможливо змінити собі через фронтенд чи RLS.
- Студент: читати заняття своєї групи та спільні, переглядати повідомлення, редагувати профіль.
- Викладач: створювати/міняти/видаляти власні заняття; для груп — тільки тих, до яких його додали як викладача; дивитися історію власних дій.
- Адміністратор: керує усіма заняттями, групами, членством, ролями, бачить загальну історію.
- Уроки прив'язані до конкретної дати. Тиждень / місяць, назад / вперед / сьогодні / вибір дати, пошук і фільтри.
- Поля: назва, дата, початок/кінець, автоматична тривалість, викладач, група, аудиторія, примітки, онлайн-посилання, матеріали, Д/з, статус.
- Аудит: тригер БД фіксує старі/нові значення, автора, роль та час, у тому числі переміщення й видалення. Клієнти не можуть змінювати журнал.
- Сповіщення в самому сайті про зміни у групі/спільному розкладі; позначення «прочитано» через захищену RPC.
- CSV із BOM та роздільником `;` відкривається в Excel, друк календаря на PDF через браузер.
- Адаптивний дизайн і темна тема, збережена у браузері.

## Що ПОКИ НЕ реалізовано

Email-розсилка про зміни, завантаження файлів у Supabase Storage (можна додавати URL), повторювані заняття, автоматичні нагадування, відновлення з аудиту однією кнопкою, поглиблені фільтри історії і вбудований генератор PDF. Їх можна додати наступним етапом. Відновлення пароля працює через email-посилання та форму нового пароля (потрібно налаштувати URL у Supabase Auth).

## Безпечне оновлення з v1 (твій уже запущений сайт)

1. **Резервна копія.** Supabase → Table Editor → `lessons` → Export CSV. Скопіюй GitHub-репозиторій або створи окрему гілку `backup-v1` із поточного `main`. SQL додатково створить закриту копію `studyflow_backup.lessons_v1`.
2. **Перевір у приватному тестовому проєкті (рекомендовано).** Для production узгодь коротке технічне вікно: після SQL стара версія перестане читати уроки до оновлення фронтенду.
3. Supabase → **SQL Editor** → New query → встав **весь** `supabase/upgrade_v2.sql` → Run. Це міграція для вже наявної таблиці `public.lessons`; запускається ОДИН раз. **Не запускай старий `schema.sql`**.
4. Supabase → Authentication → Providers → Email: увімкни email/password. Може бути ввімкнено підтвердження пошти; перевір SMTP / ліміти Supabase.
5. Зареєструй **власний** акаунт на v2, потім в Supabase SQL Editor признач йому адміністратора (заміни email):

```sql
UPDATE public.profiles SET role = 'admin'
WHERE id = (SELECT id FROM auth.users WHERE email = 'ТВОЯ_ПОШТА@example.com');
SELECT id,full_name,role FROM public.profiles WHERE role='admin';
```

   Цю команду запускай **тільки** в Supabase SQL Editor із правами власника, ніколи в коді сайту. Для першої реєстрації можна тимчасово запустити v2 у Vercel Preview з окремої гілки після міграції, або зробити акаунт у Supabase Auth → Add user і тоді надати роль через SQL. Після призначення ролі перезайди/онови сторінку.
6. **Публікація коду.** На [GitHub](https://github.com/IlliaBorshchuk2007/studyflow-rozklad) завантаж **вміст** цієї папки у корінь репозиторію (файл `package.json` має бути в корені). Через GitHub можна завантажити нові/замінити існуючі файли; рекомендовано через git CLI:

```bash
# у розпакованій папці v2, після перевірки міграції:
git clone https://github.com/IlliaBorshchuk2007/studyflow-rozklad.git
# Скопіюй ВМІСТ папки studyflow-v2 у клонований репозиторій, замінивши старі файли.
# Видали невикористані старі файли (наведено нижче).
cd studyflow-rozklad
git add -A
git commit -m "StudyFlow v2: auth roles calendar audit notifications"
git push origin main
```

   **Старі файли, які треба видалити під час оновлення:** `src/App.jsx`, `src/main.jsx`, `src/lib/supabase.js`, `src/lib/utils.js`, `vite.config.js`, `tests/utils.test.js` (нові версії .tsx/.ts уже в архіві). У TS-коді імпорти містять `.tsx`/`.ts`, тому навіть до видалення старі файли не підмінять нові при резолвінгу.
7. **Vercel.** Після `git push` Vercel автоматично збере нову версію з GitHub. Змінні Vercel НЕ потрібно змінювати, якщо вже існують:

```dotenv
VITE_SUPABASE_URL=https://ВАШ_ПРОЄКТ.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_ВАШ_КЛЮЧ
```

   Framework preset: `Vite`; Build Command: `npm run build`; Output directory: `dist`; Root directory: `./`.
8. Відкрий адресу Vercel, зареєструйся / увійди, створи групу, додай викладача, перевір урок, історію, сповіщення, відсутність кнопки редагування у студента. Спробуй під одним студентом прямий запит на редагування: RLS має повернути відмову.

## Локальна перевірка

Потрібен Node.js 20.19+ (або Node 22+):

```bash
npm install
cp .env.example .env.local
# заповни лише публічні змінні Supabase у .env.local
npm run build
npm test
npm run dev
```

Не додавай у frontend `service_role`, `secret`, `sb_secret_...`. Не публікуй `.env.local` у GitHub. `.gitignore` його виключає.

## Додаткові примітки

- Старі щотижневі записи v1 після міграції потраплять на дати **поточного тижня** (за Києвом) у відповідні дні; це разове перетворення, а не автоматичне повторення. За потреби перенеси їх у календарі.
- `group_id = NULL` означає спільний урок для всіх авторизованих. Нові заняття для конкретних груп видно лише їхнім учасникам, викладачу і адміну.
- Повідомлення надсилаються учасникам відповідної групи; про спільні уроки — всім користувачам. Для великих систем потрібен фонова черга розсилки, але для невеликої групи вистачає тригера.
- Дозволи перевіряються на рівні Supabase RLS; приховані кнопки в інтерфейсі — лише зручність.
- Для відновлення пароля у Supabase → Authentication → URL Configuration встанови **Site URL** на адресу Vercel та додай `https://studyflow-rozklad.vercel.app/**` до Redirect URLs. Перевір лист у тестовому акаунті.

## Оновлення StudyFlow 2.1 — статус «Проведено»

У редакторі заняття додано статус **Проведене**. Він відображається зеленою міткою на картці, враховується у статистиці та фіксується в історії змін, коли викладач або адміністратор редагує урок.

**Для чинної бази Supabase v2 перед публікацією нової версії** один раз виконайте у SQL Editor файл `supabase/add_completed_status.sql`. Він дозволяє четвертий статус, зберігає уроки та не змінює RLS. Після успішного SQL опублікуйте оновлення Vercel.
