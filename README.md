# StudyFlow — спільний розклад уроків 📚

Готовий сайт українською мовою: **7 днів на одній сторінці**, заняття з часом початку/кінця, тривалістю, приміткою та посиланням; створення, зміна й видалення будь-яким відвідувачем. Загальна статистика та локальний профіль із персональними показниками. Зміни синхронізуються між браузерами через Supabase Realtime (резервно перевіряються раз на 45 секунд).

**Стек:** React 19, Vite 7, Supabase (PostgreSQL + Realtime), Vercel, GitHub.

## 1. Що потрібно

- Обліковий запис на [github.com](https://github.com/).
- Обліковий запис на [supabase.com](https://supabase.com/).
- Обліковий запис на [vercel.com](https://vercel.com/) (можна увійти через GitHub).
- Для запуску **на комп'ютері** — [Node.js](https://nodejs.org/) **20.19+ або 22.12+** (рекомендовано актуальний LTS) і Git, якщо плануєте завантажувати репозиторій із термінала.

## 2. Налаштування Supabase — обов'язково

1. Відкрий [Supabase Dashboard](https://supabase.com/dashboard) → **New project**.
2. Вкажи назву, наприклад `studyflow`, придумай сильний пароль **бази даних** (цей пароль нікому не передавати) і обери регіон. Дочекайся створення проєкту.
3. У лівому меню відкрий **SQL Editor** → **New query**.
4. Відкрий файл [`supabase/schema.sql`](supabase/schema.sql), скопіюй **весь вміст**, встав у SQL Editor та натисни **Run**. Створиться таблиця `public.lessons`, політики публічного читання/редагування та Realtime. Цей SQL можна запускати повторно.
5. Перевір **Table Editor → lessons** (таблиця повинна існувати). Для синхронізації також можна перевірити **Database → Publications → supabase_realtime** (таблиця `lessons` повинна бути увімкнена).
6. Відкрий **Project Settings → API Keys** або вкладку **Connect** в Supabase. Знайди:
   - **Project URL**: `https://abcdefghijk.supabase.co`
   - **Publishable key**: починається з `sb_publishable_...`; якщо в старому проєкті є лише legacy `anon` key, його також можна використовувати в `VITE_SUPABASE_PUBLISHABLE_KEY`.
7. **Ніколи не вставляй** `service_role`, `sb_secret_...`, пароль бази чи інші секрети в `.env`, в GitHub або у Vercel-перемінні з префіксом `VITE_`. Клієнтський publishable ключ може бути публічним, а права визначають RLS-політики.

### Важливо про відкритий доступ

За твоїм запитом **немає входу та пароля**. Тому **будь-хто, хто відкрив сайт (і навіть хто дістав його публічний ключ), зможе читати, змінювати та назавжди видаляти будь-які уроки**. Не додавай конфіденційних даних. Це підходить лише для довіреної невеликої групи; це **не** приватне посилання і **не** захист від сторонніх людей. Якщо пізніше потрібна приватність, треба додати авторизацію й суворіші RLS-політики. Вбудоване поле "Мій профіль" **локальне**, не захищене обліковим записом.

## 3. Запуск на комп'ютері

Відкрий термінал у папці з файлом `package.json`:

```bash
npm install
```

Створи `.env` у корені проєкту (скопіюй `.env.example`) і підстав **свої** значення:

```dotenv
VITE_SUPABASE_URL=https://abcdefghijk.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_ТУТ_ТВІЙ_КЛЮЧ
```

Запусти:

```bash
npm run dev
```

Відкрий адресу, яку показав термінал (зазвичай `http://localhost:5173`). Для перевірки збірки:

```bash
npm run build
```

Перевірка вбудованих тестів утиліт (не потребує npm-пакетів):

```bash
npm test
```

Збірка потрапить у папку `dist/`.

> Без налаштованих `VITE_...` сайт **працює в деморежимі** з демонстраційними уроками, але зміни зберігаються **лише в одному браузері**. Це не спільне сховище. Після налаштування Supabase демодані зникнуть, бо завантажаться справжні дані таблиці.

## 4. Завантаження проєкту на GitHub

**Спосіб A — через термінал:**

1. На GitHub → **New repository** → назва `rozklad-urokiv`, доступність **Public** або **Private** (обидва варіанти підходять для деплою з Vercel), **не додавай README чи .gitignore автоматично**.
2. Виконай у папці проєкту:

```bash
git init
git add .
git commit -m "Initial commit: StudyFlow schedule"
git branch -M main
git remote add origin https://github.com/ТВІЙ_ЛОГІН/rozklad-urokiv.git
git push -u origin main
```

Замінити `ТВІЙ_ЛОГІН` на свій GitHub-логін. Якщо Git попросить авторизацію — пройди її у браузері/через Git Credential Manager.

**Спосіб B — без термінала:** створи порожній репозиторій на GitHub → **Add file → Upload files** → завантаж **вміст розпакованої папки** (разом із `src`, `supabase`, `package.json`, `vercel.json` та іншими файлами) → **Commit changes**. Деякі браузери не завантажують приховані файли (`.gitignore`, `.env.example`) перетягуванням; їх можна додати вручну через **Add file → Create new file**. **Не завантажуй справжній `.env`**.

## 5. Розгортання на Vercel

1. Відкрий [vercel.com/new](https://vercel.com/new), увійди через GitHub.
2. Вибери **Import Git Repository** → `rozklad-urokiv` → **Import**. Якщо репозиторій не видно, дозволь Vercel доступ до репозиторію на GitHub.
3. Перевір параметри:
   - **Framework Preset:** `Vite` (зазвичай визначається автоматично).
   - **Root Directory:** `./` (корінь репозиторію).
   - **Build Command:** `npm run build`.
   - **Output Directory:** `dist`.
4. До натискання **Deploy** розкрий **Environment Variables** та додай **дві окремі змінні**:
   - `VITE_SUPABASE_URL` → URL твого проєкту.
   - `VITE_SUPABASE_PUBLISHABLE_KEY` → твій **публічний** ключ (`sb_publishable_...` або legacy `anon`).
5. Натисни **Deploy**. Коли збірка завершиться, Vercel видасть URL на кшталт `https://rozklad-urokiv-xxxx.vercel.app`.
6. Відкрий адресу з комп'ютера й телефона. Натисни **Додати урок**, заповни форму і збережи. Відкрий той самий URL в іншому браузері — урок має з'явитися. Редагування доступне в обох браузерах.
7. Кнопка **Поділитись** копіює адресу сайту. Усім, кому надішлеш URL, буде доступна одна база даних.

**Якщо вже натиснув Deploy без змінних:** Vercel → твій проєкт → **Settings → Environment Variables**, додай обидві змінні та виконай **Deployments → Redeploy**. Змінні `VITE_` вбудовуються у збірку: після їх зміни обов'язковий новий деплой.

Після кожного `git push` до `main` Vercel автоматично публікує нову версію сайту. Вимикати власний комп'ютер можна — сторінка працює на Vercel, а дані зберігаються в Supabase. **Зауваження:** безоплатний Supabase може призупиняти неактивні проєкти, а хмарні сервіси не гарантують 100% доступності. Для тривалої безперервної роботи перевір умови планів і налаштуй резервні копії.

## 6. Як користуватися

- **7 днів** від понеділка до неділі в одній сітці, яка підлаштовується під екран. Це **повторюваний щотижневий розклад**, не календар із датованими/разовими подіями.
- Натисни **Додати урок** над розкладом або всередині конкретного дня.
- Введи назву й день, вибери початок, закінчення і **тривалість** (від 1 до 480 хвилин). Зміна тривалості автоматично змінює завершення; можна також вручну змінити завершення. **Урок не може переходити через північ.**
- За бажанням додай примітку та посилання (`https://...`).
- Щоб змінити або видалити урок, натисни **олівець** на його картці. Видалення потребує підтвердження.
- **Статистика:** загальна кількість занять, годин, найактивніший день, наступний урок, графік кількості уроків за днями та середня тривалість.
- **Мій профіль:** ім'я (псевдонім), кількість створених цим браузером уроків та години цих уроків. Ідентифікатор браузера зберігається у `localStorage`, а не у Supabase Auth. На іншому пристрої або після очищення даних браузера профіль буде новим. Власність уроків не перевіряється — будь-хто може змінити будь-який урок.
- Відлік сьогоднішнього дня та наступного заняття прив'язаний до **часового поясу Europe/Kyiv**.
- Supabase Realtime оновлює змінений розклад у відкритих вкладках, а також передбачено резервне опитування кожні 45 секунд та при поверненні на вкладку.

## 8. Типові проблеми

- **На Vercel видно жовтий блок «Демонстраційний режим».** Не задано або помилково написано `VITE_SUPABASE_URL` чи `VITE_SUPABASE_PUBLISHABLE_KEY`; після виправлення зроби **Redeploy**.
- **«Не вдалося завантажити уроки» / `Could not find the table...`** Не виконав `supabase/schema.sql` у правильному Supabase-проєкті, або не збігається URL.
- **`permission denied`, `42501` чи `new row violates row-level security policy`.** Перевір, що SQL виконано цілком і RLS-політики та `GRANT` присутні.
- **Сайт показує новий урок лише після перезавантаження.** Перевір у Supabase, що `lessons` включено в `supabase_realtime`. Резервна перевірка виконується кожні 45 секунд.
- **GitHub випадково отримав `.env`.** Видали його з репозиторію та історії комітів, а якщо потрапив секретний ключ — негайно перевипусти його. У цьому проєкті слід використовувати тільки publishable key.
- **Node/npm помиляється щодо версії.** Онови Node.js до актуальної LTS; для Vite 7 потрібна Node.js 20.19+ або 22.12+.
